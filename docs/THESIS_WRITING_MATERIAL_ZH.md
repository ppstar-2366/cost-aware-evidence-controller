## 2. 任务定义建议

可将单篇论文表示为证据单元集合：

```text
D = {u_1, u_2, ..., u_n}
```

其中单元类型包括摘要、正文块、表格 caption 和图片 caption。给定问题 `q`，证据选择方法输出子集：

```text
S(q, D) ⊆ D
```

目标不是单独最大化证据召回，而是在召回质量 `Q(S)` 与阅读成本 `C(S)` 之间取得折中。本文用检索证据的估算 token 数作为成本代理，并用金证据覆盖率和问题命中率评价质量。

建议不要在没有实际优化器的情况下写成“求解某个严格最优化目标”。本系统是规则控制策略，可以写成：

> 本文以质量—成本联合目标作为设计原则，通过问题类型触发不同的证据扩展动作，并显式记录每一步新增证据与停止原因。

## 3. 数据与预处理段落素材

可改写为：

> 实验采用 QASPER 科学论文问答数据。为适配本地资源，本研究处理了训练 split 前 100 篇和验证 split 前 50 篇论文。最终评估使用验证子集中的 50 篇论文、156 个问题，其中 151 个问题具有标注证据，共包含 395 条去重后的金证据片段。预处理将论文标题、摘要、正文 section 及图表 caption 转换为结构化证据单元；正文按最多 250 词切分，相邻块重叠 40 词。验证子集最终包含 1,574 个证据单元，其中正文块 1,129 个、表格 caption 206 个、图片 caption 139 个、摘要 50 个和标题 50 个。

需要同时说明：

- split 取前 N 篇，不是随机采样；
- title 被保存但不进入正式检索；
- final controller 不进行机器学习训练；
- 训练子集不是最终指标来源。

## 4. 方法段落素材

### 4.1 BM25 基线

> 对每篇论文单独建立 BM25 索引，以避免跨论文检索造成额外干扰。文本转为小写后用英文字符、数字和下划线组成的正则 token 进行分词。本文设置 k∈{1,3,5,10,20}，从而观察固定证据预算增加时覆盖质量和阅读成本的变化。

### 4.2 ControllerV3

> ControllerV3 首先读取 BM25 排名前 3 的证据单元，然后根据问题类型采取扩展动作。结果或数据问题扩大到全局前 7，并优先加入表格；数据问题进一步检索数据集或实验设置相关 section。方法类和复杂问题扩大到前 7，未匹配类型的问题采用默认前 5。定义或缩写问题优先从摘要、引言、背景和概述 section 中增加定义证据。图示类问题额外检索图片 caption。所有动作按 unit ID 去重，并保存动作名称、新增数量与停止原因，使每个问题的证据选择过程可追踪。

### 4.3 消融设计

> 为检验章节信息的独立贡献，本文构造 ControllerV3_no_section：保留相同的初始 top-3、问题分类、全局扩读、表格/图片和停止规则，仅关闭定义问题及数据问题的章节感知扩展。两种控制器在相同验证样本和相同检索评估指标下比较。

## 5. 指标定义素材

对每条金证据 `g` 与检索单元 `u`，定义：

```text
Overlap(g,u) = |T(g) ∩ T(u)| / |T(g)|
```

其中 `T(·)` 是去重 token 集合。每条金证据在全部检索单元上取最大 overlap。

建议用语：

> 当最大 overlap 不低于 0.5 时，认为该金证据被覆盖。Evidence Recall 统计全部 395 条金证据中被覆盖的比例；Question Hit Rate 统计 151 个具有标注证据的问题中，至少有一条金证据被覆盖的比例。Average Best Overlap 则保留连续覆盖程度。

成本：

```text
EstimatedTokens = round(AverageEvidenceWords × 1.3)
RecallPer1k = EvidenceRecall / EstimatedTokens × 1000
```

需要写清楚 `EstimatedTokens` 是成本代理，不是模型 tokenizer 的真实 token。

答案指标：归一化后计算 token F1 和 Exact Match，一个问题对多个参考答案取最大值，最后对 156 个问题做宏平均。

## 6. 论文主表：检索结果

建议表题：**不同证据选择方法在 QASPER validation_50 上的检索质量与成本比较（overlap threshold=0.5）**。

| 方法 | Evidence Recall | Question Hit Rate | Avg. Evidence Units | Avg. Estimated Tokens | Recall/1k Tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| BM25 top-1 | 0.2304 | 0.3444 | 1.00 | 216 | 1.0667 |
| BM25 top-3 | 0.4253 | 0.5894 | 3.00 | 678 | 0.6273 |
| BM25 top-5 | 0.5646 | 0.7748 | 5.00 | 1,156 | 0.4884 |
| BM25 top-10 | 0.7772 | 0.9007 | 10.00 | 2,322 | 0.3347 |
| BM25 top-20 | 0.9519 | 0.9801 | 19.53 | 4,144 | 0.2297 |
| ControllerV3 | 0.7063 | 0.8675 | 7.69 | 1,640 | 0.4307 |
| ControllerV3 w/o section | 0.6759 | 0.8344 | 7.24 | 1,543 | 0.4380 |

结果讨论建议：

> 固定 top-k 的结果呈现清晰的单调趋势：k 从 1 增至 20 时，Evidence Recall 从 0.2304 提高至 0.9519，但平均估算 token 从 216 增至 4,144。与此同时，Recall per 1k Tokens 持续下降，说明后续证据的边际覆盖收益逐渐减小。

> ControllerV3 使用平均 1,640 个估算 token，取得 0.7063 的 Evidence Recall 和 0.8675 的 Question Hit Rate，其质量与成本均位于 BM25 top-5 和 top-10 之间。相对 top-10，ControllerV3 减少约 29.4% 的估算 token，Recall 和 Hit Rate 分别下降 7.09 与 3.32 个百分点。因此，它的优势应解释为可控预算下的质量—成本折中，而不是超过高预算 BM25 的绝对召回。

不要写“ControllerV3 的 token 效率最高”。低 k 的 Recall/1k 更高，但绝对质量不足。

## 7. 论文主表：消融结果

建议表题：**章节感知扩展的消融实验**。

| 方法 | Recall | Hit Rate | Avg. Best Overlap | Avg. Units | Est. Tokens | Recall/1k |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| ControllerV3 w/o section | 0.6759 | 0.8344 | 0.6993 | 7.24 | 1,543 | 0.4380 |
| ControllerV3 | 0.7063 | 0.8675 | 0.7231 | 7.69 | 1,640 | 0.4307 |
| 绝对变化 | +0.0304 | +0.0331 | +0.0238 | +0.45 | +97 | -0.0073 |

可改写为：

> 加入章节感知扩展后，Evidence Recall 提升 3.04 个百分点，Question Hit Rate 提升 3.31 个百分点，Average Best Overlap 提升 2.38 个百分点；代价是平均增加 0.45 个证据单元和约 97 个估算 token。消融结果说明相关 section 信息确实改善了证据覆盖，但额外扩展也使 Recall per 1k Tokens 略有下降，体现了质量与成本之间的权衡。

## 8. 论文主表：下游回答结果

建议表题：**本地 Qwen2.5-3B 在不同检索证据上的回答结果**。

| 方法 | Answer F1 | Exact Match | Avg. Prompt Tokens | Avg. Output Tokens | Success |
| --- | ---: | ---: | ---: | ---: | ---: |
| BM25 top-5 | 0.2591 | 0.1218 | 1,243.39 | 8.95 | 156/156 |
| BM25 top-10 | 0.2629 | 0.1282 | 1,309.10 | 10.19 | 156/156 |
| BM25 top-20 | 0.2577 | 0.1218 | 1,309.10 | 9.93 | 156/156 |
| ControllerV3 | 0.2577 | 0.1218 | 1,295.44 | 9.96 | 156/156 |

建议讨论：

> 四种方法的宏平均 F1 位于 0.2577—0.2629，EM 位于 0.1218—0.1282。ControllerV3 与 BM25 top-20 的 F1 几乎相同，且与 top-5/top-10 的差异也较小。逐问题比较中，ControllerV3 与 top-20 有 148/156 个问题 F1 相同，与 top-10 有 143/156 个问题相同。结果表明在当前固定提示词预算和本地 3B 生成器下，ControllerV3 的证据可以维持相近的下游问答表现。

必须紧接着披露：

> 生成提示词对证据部分设置了 6000 字符上限。审计显示 BM25 top-10 与 top-20 的 156 对 prompt 全部相同，ControllerV3 与 top-10 也有 134/156 对相同。因此，该实验主要验证固定上下文预算下的下游可用性，不能用来判断 top-20 额外证据的生成贡献。相同 top-10/top-20 prompt 仍产生 9 对不同输出，也说明跨时段本地推理并非逐字符完全确定。

不要把 BM25 top-10 的 0.2629 与 Controller 的 0.2577 写成显著差异；没有统计检验，且差值仅 0.0052。

## 11. 有效性威胁建议段落

可以分为：

### 内部有效性

- Controller 规则由 validation 子集的错误观察推动，开发和最终评估未严格分离；
- 生成跨多次续跑，本地推理未逐字符完全确定；
- wall-time 受休眠、缓存和模型加载影响。

### 构念有效性

- overlap≥0.5 是词法覆盖代理，不等于语义相关性；
- word×1.3 是成本代理，不是实际 tokenizer；
- F1/EM 对长答案和语义等价表述不够敏感。

### 外部有效性

- 只评估 validation 前 50 篇；
- 仅 QASPER 和英文科学论文；
- 仅 BM25、规则控制器和 Qwen2.5-3B；
- 不能直接推广到其他领域或更强生成模型。

## 12. 贡献表述建议

稳妥、可答辩的贡献写法：

1. 构建了面向科学论文问答的结构化证据处理与评估流水线，统一处理正文、摘要、表格和图片 caption。
2. 设计了一个轻量、问题类型感知、动作可追踪的证据控制器，以动态扩展替代单一 fixed top-k。
3. 从证据覆盖、问题命中、阅读成本和单位成本召回多个维度评估方法，并用章节扩展消融验证模块贡献。
4. 在本地 3B 模型上完成 624 次下游生成，验证低资源条件下的端到端可运行性，并对 prompt 上限与非完全确定性进行审计。
5. 提供逐问题错误类别和完整复现档案，明确方法适用边界。

避免使用“首创”“显著优于”“达到 SOTA”“证明泛化”等没有外部对比或统计证据的表述。

## 13. 答辩常见问题与回答要点

### 为什么不用付费 GPT API？

本研究强调低资源和可复现性。本地 Qwen2.5-3B 让全部生成可以在同一模型、无按次成本的条件下完成。生成器不是研究创新主体，核心是证据选择与成本控制。

### 为什么 BM25 top-20 召回最高，却还需要 Controller？

top-20 平均需要约 4,144 个估算 token，而 Controller 为 1,640，减少约 60.4%。Controller 的研究价值是显式预算和可解释动作，不是争夺最大召回。

### 为什么 Controller 的 Recall/1k 不如 top-5？

覆盖更多长尾证据会出现边际收益下降。top-5 的单位成本比值较高，但绝对召回只有 0.5646；Controller 用更多预算把召回提高到 0.7063。二者针对不同质量要求。

### 消融的效率值反而略高，是否说明章节扩展无用？

不说明。章节扩展用约 97 个额外 token 换来 3.04 个百分点 recall 和 3.31 个百分点 hit rate。若只追求比值可选消融；若需要更高覆盖，完整版本更合适。

### 为什么生成 F1 较低？

QASPER 问题复杂，参考答案形式多样；生成器是本地 3B 小模型，prompt 采用严格证据约束。论文把生成作为下游验证，主要贡献仍是检索质量、成本、消融和错误分析。

### top-10 与 top-20 为什么 F1 不同但 prompt 相同？

两者受 6000 字符证据上限影响，156 对输入全部相同；跨时段 Ollama 推理仍有 9 对输出不同。微小 F1 差异应归因于推理非完全确定性，不能归因于额外 top-20 证据。

### 最需要补做的实验是什么？

若有时间，冻结 ControllerV3 后在完全未用于规则设计的新子集上复现，是优先级最高的补充；其次是 bootstrap 置信区间、dense baseline 或人工忠实性评估。现有实验已经形成完整原型闭环，但这些补充会增强泛化论证。
